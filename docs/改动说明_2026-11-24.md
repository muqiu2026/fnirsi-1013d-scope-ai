# 示波器串口桥接 · 优化与中文化改动说明（2026-11-24）

## 一、环境约束（必须先读）

- 本机（Windows）与云主机（Ubuntu）**均无 ARM/Allwinner 交叉编译链**（无 arm-none-eabi-gcc、mksunxi、flashfilepacker、sunxi-fel），**固件 .bin 无法在本机编译打包，也无法烧录上机验证**。
- 因此固件侧改动目前只落到 **C 源码 / 字库数据文件**，需在原有 NetBeans + GNU_ARM-Linux 工具链环境编译、烧录后才生效。上位机 Python 脚本可本机直接运行、已连 COM26 实测。
- 真机当前固件版本：`V1.3.0C MOD V9B4`；源码基线目录 `Scope v0.28a`，两者未逐文件比对。

## 二、已落地并实测通过（上位机，COM26 @2000000）

文件：`scope_bridge.py`（`scope_ai.py` 本轮未改，口径本就正确）

1. **抓帧节流**：新增 `MIN_FRAME_INTERVAL=0.12s`，收到一帧后距上次请求不足间隔不再连续追帧，给固件主循环留出采集/刷屏时间，避免满载 HEX 打包拖慢整机（跳闪根因之一）。实测 4 秒约 32 帧（≈0.125s/帧）。
2. **参数解析同源**：`parse_frame` 改为直接复用 `scope_ai.py` 的 `parse_prm()` 与档位/采样率表，消除 bridge 与控制库两套口径漂移。
3. **采样率定标统一**：每点时间 `dt` 改用固件采样率表算出的 `sample_dt`，不再用旧的 `时基/100` 反推（其它时基档会偏差）。
4. **探头映射对齐**：探头倍率复用 `WEB_PROBE_TEXT`（1x/10x/100x），去掉重复拼接的 `X`；电压档位直接用带单位文本。
5. **网页前端中文化**：运行（运行/停止）、触发模式（自动/常规/单次）、触发沿（上升沿/下降沿）、时基文本均中文化；标签单位（AC/DC、CH1/CH2、V/div、Sa/s）保留仪器通用符号。
6. 实测：`status` / `report` / 抓帧 / 设时基读回均正常；1kHz 方波 周期 1.000ms、占空比约 50%，与历史实测一致。

## 三、已改固件源码（待工具链编译，未上机验证）

目录：`firmware\repos\Atlan4\Scope v0.28a\`；原始备份 `usb_interface.c.bak`。

### 1. `usb_interface.c`
- **删除 `#WAV2,2` 假数据分支**：旧分支回传 `(j%254)+1` / `((k+128)%254)+1` 锯齿，是调试假波形；现改为回 `#ERR,UNKNOWN`，避免上位机误取假数据。
- **`#WAV2,3` 波形裁剪到 3000 真实点**：原打包 4801 点/通道（后 1801 点是 128 填充），上位机只取前 3000 点；现只打包 3000 点，减少阻塞主循环的 HEX 打包量约 37%。
- **CH2 关闭时不打包第二段**：恢复被注释掉的通道使能判断；CH2 关时帧内不带 CH2 段（上位机已兼容：无第二段即 CH2 无数据）。
- 保留帧头 `#OK,` + 320 字节 SysParam 打包；CH1 校准链（input_calibration）保持原样，未改动 CH2 未校准的现状。
- 帧格式变化：`#OK,<320B 参数HEX>,<CH1 3000点HEX>[,<CH2 3000点HEX>]\n`。

### 2. 中文字库（`chinese_font.c/.h`，两处目录已同步）
- 生成器：`firmware\gen_chinese_font.py`（PIL + 系统黑体取模，本机可跑）。
- 翻译条目 170 → **194**，字模 199 → **208**（新增 9 个汉字）。
- 新增安全可译的上屏词条：小时/分钟/月/年、长存储/平均/快/慢/上/下、模式/边沿/总是/关/输入、参考1..8、“请复位数值！”。
- **保留英文未译**：测量缩写（Vmax/Vmin/Vavg/Vrms/Vpp/Vp/Freq/Cycle/Tim±/Duty±）、波形名（Sine/Square/Triangle）、单位、型号、数学式与映射链（`CH1=>A` 等）、内部调试名。原因：多为窄密排网格标签，中译易溢出，且行业沿用英文缩写。
- 已静态校验：194 条全部命中、所有翻译汉字均有字模、无缺字。

## 四、本次未做（高风险 / 需工具链环境 + 上机目视验证）

下列为跳闪治本项，改动跨文件、影响控制流，本机无编译链无法验证，**未写入源码**，避免交付可能导致界面漏刷/撕裂却无法发现的改动：

1. **局部刷新**：`scope_control.c` 的 `refresh_all()` 每条命令全量重绘 RUN/CH1/CH2/触发 4 块。可按块拆分（`refresh_run/refresh_ch/refresh_trig`），setter 只刷相关块；注意通道开关↔触发按钮存在联动（`ctl_channel_enable` 现手动调 `scope_trigger_settings`），拆分时必须保留该联动，否则触发按钮残留旧值。
2. **延迟刷新（ui_dirty）**：命令回调只置刷新标志/块掩码，不在回调里阻塞刷屏；在主循环采集流程之后统一消费标志。需把“参数生效”与“界面刷新”分离，跨 `scope_control.c` / `fnirsi_1013d_scope.c`（主循环 `usb_CDC_receive_callback()` 在 while(1) :347 同步插队）。
3. **双缓冲 / 帧同步**：现单块显存被 TCON 直接扫描，拷贝中途被扫到即撕裂；需第二缓冲 + TCON layer 地址切换。可行性取决于 DRAM 余量与 TCON layer base 寄存器能力，尚未核实。
4. **二进制波形帧**：`#WAV2,3` 现为数千点 ASCII HEX，打包阻塞主循环；可改二进制帧（如 `#WAV2,BIN`）大幅缩短传输与打包时间，需同步改上位机解析。
5. 协议层建议（后续）：复合命令一次下发一次刷新；探头/档位口径统一；`#READ` 按字段读；no-op 按键与成功区分状态码；错误码带原因；电平/位置标注单位量程。
