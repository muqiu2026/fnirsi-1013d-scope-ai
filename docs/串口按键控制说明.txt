结论先说：
==========

1. 网页 App 里确实有 “#KEY,xx” 这种模拟按键命令。
2. 但你当前这台 ADS1013D 刷的 v0.27r APP 开源固件，源码里没有实现 #KEY 命令处理。
   所以网页上很多按键没反应，不是电脑/串口的问题，是固件端没有真正执行这些命令。
3. 当前固件真正支持的串口命令只有这些：
      #VER        查询版本
      #INFO       返回 1013D
      #ECHO,xxx   回显测试
      #RUN        只回 #OK,RUN，源码里没有真正改变运行状态
      #STOP       只回 #OK,STOP，源码里没有真正改变运行状态
      #SET,xxx    只回 #OK,SET，源码里没有真正执行设置
      #READ       读参数区
      #WAV2,2     返回模拟/测试波形，不是真实采样
      #WAV2,3     返回真实波形（前 3000 点是 ADC 采样）
   其他命令会返回：
      #ERR,UNKNOWN

所以，严格回答你的问题：
   串口协议“字符串形式”能发按键命令；
   但当前固件“不会执行”屏幕按键功能。
   要让 AI/电脑真正操作示波器按键，需要改固件，把 #KEY 命令接到菜单/按键处理函数上。

真正可用的数据命令
==================

当前最有用的是：

   发送：
      #WAV2,3

   返回：
      #OK,<320字节参数HEX>,<CH1数据HEX>,<CH2数据HEX>

   其中：
      - 参数区 320 字节 = 640 个 HEX 字符
      - CH1/CH2 每段是 4801 字节 = 9602 个 HEX 字符
      - 前 3000 点是真实 ADC 采样
      - 后面到 4801 的 128 是填充值
      - ADC 值 128 约等于 0V

注意：
   源码里 #WAV2,2 的 CH1 数据是 (j % 254) + 1 的测试斜坡，不是真实波形。
   所以不要用 #WAV2,2 做真实硬件调试。
   之前脚本里用的 #WAV2,1 在当前固件里也不支持，会返回 #ERR,UNKNOWN。
   现在已经把两个脚本都改成 #WAV2,3。


AI 数据方案现状
================

已修正并可用：

   scope_capture.py
      双击版数据捕捉脚本，自动找串口、自动请求 #WAV2,3、写 live_scope.txt。

   dist\示波器数据捕捉器.exe
      上面脚本打包出来的 exe。双击后会持续刷新同目录下的 live_scope.txt。
      把 live_scope.txt 交给 AI，AI 可以直接读 Vpp、频率、占空比、RMS、噪声、
      波形形状、异常提示和 200 点降采样数组，不需要截图识别。

   scope_bridge.py
      功能更全的桥接器：写 live_scope.txt，同时启动 http://localhost:8765
      给人实时看波形。使用命令：
         python scope_bridge.py COM26


如果想真的让 AI 操作按键
========================

有两条路：

A. 找/编译一个已经实现 #KEY 的固件
   目前从 pecostm32、Atlan4 两个主要开源仓库和 v0.27r APP 源码里都没有找到
   1013D 上真正实现 #KEY 的版本。需要继续找 DSO2512G 那套固件移植版。

B. 改现有 v0.27r APP 固件
   在 usb_interface.c 的 usb_CDC_receive_callback() 里加：
      else if (strncmp(rx_buffer, "#KEY,", 5) == 0)
      {
          uint8 key = hex_to_byte(&rx_buffer[5]);
          scope_key_handler(key);   // 调用现有菜单/按键处理函数
          usb_CDC_send_text("#OK,KEY\n");
      }
   难点是要把 key 码映射到菜单源码里的实际按键处理函数。
   这部分需要编译 ARM 固件并重新刷 SD 卡，不建议在没备份的情况下直接改。
